### Tugas 7

1. Seluruh interface dibangun dari widget yang disusun bertingkat sehingga membentuk widget tree. Setiap widget bisa punya satu or lebih anak. Hubungan parent-child bekerja dengan cara parent memberi batasan ukuran ke anak,child menentukan ukurannya sendiri dalam batasan itu, lalu parent yang mengatur posisinya. Data seperti theme juga mengalir dari atas ke bawah, sehingga widget di level bawah bisa membaca konfigurasi dari "leluhurnya". Pada aplikasi ini, pohonnya berawal dari MyApp dan MaterialApp, turun ke MyHomePage dan Scaffold, lalu ke Column yang berisi Row untuk InfoCard serta GridView untuk ItemCard.
2. MaterialApp menjadi root aplikasi, Scaffold menyediakan kerangka halaman, dan AppBar menampilkan judul di bagian atas. Padding dipakai untuk memberi jarak, Column dan Row untuk menyusun widget secara vertikal dan horizontal, Center untuk menengahkan konten, SizedBox sebagai spasi, serta GridView.count untuk menampilkan tombol dalam tiga kolom. Text dan Icon menampilkan teks dan ikon, Card dan Container membentuk kartu informasi, sedangkan Material dan InkWell membuat tombol berwarna yang bisa ditekan dengan efek ripple. SnackBar yang dipanggil lewat ScaffoldMessenger menampilkan notifikasi saat tombol ditekan. Selain itu, saya membuat widget sendiri yaitu MyApp, MyHomePage, InfoCard, dan ItemCard.
3. MaterialApp "membungkus" aplikasi dengan berbagai kebutuhan dasar widget Material, seperti tema, navigasi antarhalaman, informasi ukuran layar melalui MediaQuery, dan ScaffoldMessenger untuk SnackBar. Widget seperti Scaffold, AppBar, dan SnackBar mencari kebutuhan tersebut dari leluhurnya melalui context, sehingga tanpa MaterialApp di atasnya widget-widget itu tidak dapat berfungsi dengan benar. Karena itu MaterialApp diletakkan sebagai root agar theme dan navigasi cukup didefinisikan sekali dan berlaku di seluruh aplikasi.
4. StatelessWidget tidak menyimpan data yang dapat berubah, sehingga tampilannya hanya bergantung pada parameter yang diberikan oleh parent. Sebaliknya, StatefulWidget memiliki objek State yang menyimpan data yang bisa berubah, dan pemanggilan setState() akan membuat widget di-build ulang dengan data terbaru. StatelessWidget sebaiknya dipakai untuk tampilan statis seperti halaman menu ini, yang identitas dan tombolnya tidak berubah. StatefulWidget digunakan ketika tampilan perlu berubah akibat interaksi atau data, misalnya counter, form input, toggle, atau data yang diambil dari API.
5. BuildContext adalah penanda posisi sebuah widget di dalam widget tree, dan setiap metode build menerima context miliknya sendiri. Context digunakan dalam Theme.of(context) untuk mengambil warna AppBar, MediaQuery.of(context) untuk menghitung lebar InfoCard, dan ScaffoldMessenger.of(context) untuk menampilkan SnackBar. Context hanya dapat menemukan widget yang berada di atasnya, sehingga Theme.of bisa berjalan karena MyHomePage berada di bawah MaterialApp.
6. Hot reload memasukkan perubahan kode ke aplikasi yang sedang berjalan lalu membangun ulang widget tree tanpa menghilangkan state, sehingga perubahan tampilan bisa langsung terlihat. Hot restart menjalankan ulang aplikasi dari fungsi main(), sehingga seluruh state kembali ke kondisi awal. Hot reload tidak cukup ketika perubahan terjadi pada kode yang hanya dijalankan sekali, seperti main(), initState(), atau nilai awal variabel global dan static. Pada kasus tersebut diperlukan hot restart. Full restart atau menjalankan ulang flutter run hanya diperlukan ketika mengubah kode native atau menambahkan package baru di pubspec.yaml.
